# Unified Mjolnir file conversions

The `fileconversions` branch provides one strict, reusable conversion system for:

* Mjolnir-processed HDF5 → GRIB Edition 1;
* the migrated Mjolnir-processed HDF5 → GRIB Edition 2 path;
* GRIB2 → GRIB1 by explicit message decoding and re-encoding;
* CF-like NetCDF → GRIB1;
* GRIB structure, round-trip and GRIB1/GRIB2 parity validation.

The conversion tools do not ingest the native THOR icosahedral output as their production input. They ingest the post-processed HDF5 products generated by the existing Mjolnir workflow. The native-output processing code is inspected only to establish provenance, physical meaning, units, coordinate conventions, and validation constraints.

No RePLaT Fortran unformatted binary or other private binary format is created.

## Architecture

```text
native THOR HDF5
    │ existing Mjolnir regrid() — outside this converter
    ▼
verified Mjolnir-processed HDF5 / CF NetCDF / decoded GRIB2
    ▼
canonical (time, level, latitude, longitude), pressure in Pa
    ▼
shared grid, poles, pressure, time, missing-value and omega logic
    ├── GRIB1 writer (WMO table 2: 33, 34, 39)
    ├── GRIB2 writer (0/2/2, 0/2/3, 0/2/8)
    └── optional diagnostic NetCDF
```

Both GRIB writers consume the same `CanonicalDataset` arrays. Format-specific code begins only at parameter, level, time and packing encoding.

## What existed and what changed

The prior GRIB2 work is commit `8fe5da7` on `origin/replat`, under `replat_conversion_last100_50591_50690/`. It used `regrid_height_*.h5`, periodic bilinear remapping, explicit poles, integer-Pa/log-pressure interpolation, a standard NetCDF intermediate and CDO GRIB2 encoding. It correctly retained Mjolnir `W` as geometric `m s-1`; it did not produce omega.

This branch ports the reusable numerical behavior into modules, adds structural input classification, prevents native-grid and double transformations, adds strict physical omega modes, supplies native ecCodes GRIB writers and adds GRIB1-specific pressure safeguards. Existing generated data files were not copied into this branch. See [GRIB2_EXISTING_WORK.md](docs/GRIB2_EXISTING_WORK.md), [GRIB2_MIGRATION_MAP.md](docs/GRIB2_MIGRATION_MAP.md) and [PROVENANCE.md](docs/PROVENANCE.md).

## Mjolnir-processed HDF5 → GRIB1

```bash
.venv-fileconversions/bin/python fileconversions/scripts/hdf5_to_grib1.py \
  --input /path/to/pgrid/regrid_venus_1.h5 \
  --input-kind mjolnir-processed \
  --output-dir /outside/repository/hdf5_to_grib1 \
  --variables u v \
  --lat-step 4 --lon-step 4 \
  --level-encoding strict \
  --vertical-velocity-mode omit \
  --file-layout per-variable
```

`strict` is deliberately the default. The examined Venus pressure levels are mostly not exact multiples of 100 Pa, so a full real-data GRIB1 run stops and writes `reports/pressure_level_mapping.csv`. `hpa-rounded` is only an explicit compatibility mode with absolute and relative error limits. `ecmwf-pa` is an ecCodes extension limited to 65535 Pa and is not asserted to be generally WMO- or RePLaT-compatible.

For omega, the default `strict` mode accepts only a verified Pa/s variable. Mjolnir `W` is geometric velocity. An explicit validation experiment may use:

```bash
--vertical-velocity-mode hydrostatic
```

This computes `omega = -rho*g*w` on collocated processed fields, using `Gravit=8.87 m s-2` from the Venus planet HDF5. It is documented as a hydrostatic approximation, not an exact native model variable.

## Migrated HDF5 → GRIB2

Use the same options with `fileconversions/scripts/hdf5_to_grib2.py`. The same canonical fields, poles, pressures and time reach the GRIB2 writer. This is the reference path for parity tests and does not silently preserve the old geometric `wz` product as omega.

## GRIB2 → GRIB1

```bash
.venv-fileconversions/bin/python fileconversions/scripts/grib2_to_grib1.py \
  --input-dir /outside/repository/grib2 \
  --output-dir /outside/repository/grib2_to_grib1 \
  --level-encoding strict \
  --on-unsupported error \
  --file-layout per-variable
```

Each message is decoded, mapped, numerically read, explicitly re-encoded and reopened. Supported GRIB2 parameters are `0/2/2`, `0/2/3` and `0/2/8`. Geometric vertical velocity `0/2/9` is not relabeled. `--on-unsupported skip` records omissions in `grib2_to_grib1_mapping.csv`.

## NetCDF → GRIB1

```bash
.venv-fileconversions/bin/python fileconversions/scripts/netcdf_to_grib1.py \
  --input /path/to/input.nc \
  --output-dir /outside/repository/netcdf_to_grib1 \
  --variables u v omega \
  --regrid if-needed \
  --level-encoding strict \
  --vertical-velocity-mode strict
```

Coordinates are identified through names, `standard_name`, `axis`, units and dimensions. Existing correct grids and integer pressure levels are not interpolated again. A NetCDF `upward_air_velocity` in m/s is never emitted as omega without an explicit physical mode.

## Grid, poles and dimension order

The default target is 46 × 90: latitude `-90,-86,…,90`, longitude `0,4,…,356`. Longitude is `[0,360)` and periodic, without a duplicate 360. Scalar poles use the nearest source latitude-ring zonal mean. Both geographic horizontal components are set to zero at the exact pole, where the east/north basis is singular. This is the convention inherited from the existing GRIB2 preparation, applied identically before both writers. Arrays are always `time, level, latitude, longitude`; GRIB scan order is explicitly north-to-south and decoded back south-to-north.

## Pressure and time

Pressure is internally positive Pa and monotonic. Height-grid products reconstruct instantaneous pressure as `Rho*Rd*Temperature`, then interpolate linearly in `log(p)` without extrapolation. Mjolnir pressure-grid HDF5 and integer-Pa NetCDF coordinates are recognized as completed vertical stages to avoid double interpolation.

Model elapsed time is preserved. GRIB uses the configurable technical epoch `2000-01-01T00:00:00Z`; it is not claimed to be an Earth observation date. Sub-minute values that GRIB1 cannot preserve stop rather than truncate.

For HDF5, `--time-index/--time-indices` select the source index encoded in `regrid_<simulation>_<index>.h5`; for NetCDF and GRIB2 they select zero-based logical time positions. `--grid-file` cross-checks an optional regular Mjolnir grid and rejects native topology, while `--planet-file` overrides companion-file discovery.

## Output and validation

The default layout is `per-variable`; `per-time` and `combined` are also supported. Existing outputs are protected unless `--overwrite` is explicit. Every GRIB output has `<file>.metadata.json` with source files, planet parameters, grid, pressure levels, omega method, Git commit and pending review status.

```bash
.venv-fileconversions/bin/python fileconversions/scripts/validate_grib.py \
  --input-dir /outside/repository/grib1 \
  --input-glob '*.grib1' --edition 1 \
  --report /outside/repository/validation_report.md

.venv-fileconversions/bin/python fileconversions/scripts/compare_grib1_grib2.py \
  --grib1-dir /outside/repository/grib1 \
  --grib2-dir /outside/repository/grib2 \
  --report /outside/repository/grib1_vs_grib2_parity.csv
```

## Test status and real samples

Synthetic unit/integration coverage includes coordinates, pole conventions, dimension transposition, pressure units/interpolation/encoding, Venus-gravity omega sign, HDF5 classification, NetCDF aliases, GRIB mappings, round-trip and parity. Real-data work used the small read-only benchmark documented in [INPUT_INSPECTION.md](docs/INPUT_INSPECTION.md). Generated products are under `/home/malkouka/THOR_POE_HOST/.codex_test_outputs/mjolnir_advance/fileconversions/` and are not committed.

The 26-test suite and synthetic integration passed. The migrated real HDF5→GRIB2 smoke test passed for 60 messages with ecCodes/CDO; direct canonical round-trip maximum absolute error was `1.91e-6`, below the `1e-4` tolerance. Real full-level strict GRIB1 conversion from HDF5, GRIB2 and NetCDF, and therefore real GRIB1/GRIB2 parity, are blocked by non-representable GRIB1 pressure levels as intended. Upstream regeneration was not run because the official path requires PyCUDA/CUDA and would duplicate already available Mjolnir products.
